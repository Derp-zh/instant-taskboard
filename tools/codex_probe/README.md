# Codex接入验证模块

独立探索工具，用来验证真实会话编号、原生执行状态与任务流转规则。不会打开任务面板的正式数据目录，也不依赖面板UI。

需要本机Python 3.11及以上和已登录的Codex CLI；只使用Python标准库。测试复用当前Codex登录环境，不复制认证文件。正式面板仍为现有程序，本模块尚未嵌入其中。

## 使用

在项目目录运行规则和通信测试：

```powershell
python -m unittest discover -s tests/codex_probe -v
```

核实当前桌面会话可读取的范围，报告保存在隔离目录：

```powershell
python -m tools.codex_probe inspect --data-dir test-output/codex-probe/results
```

默认检查本进程的`CODEX_THREAD_ID`；也可明确传入`--thread-id`。该命令读取会话目录和历史轮次元数据，并测试共享代理及独立App Server。元数据不包含会话正文。独立服务中的notLoaded不能用于判断原桌面会话已停止。

建立两个临时隔离会话，实际验证结束、提问、回答后恢复及权限请求：

```powershell
python -m tools.codex_probe live --data-dir test-output/codex-probe/results-live --timeout 65
```

`live`会调用模型，消耗少量当前Codex账户额度。两个会话均为ephemeral、使用只读沙箱和隔离工作目录；验证工具只回答自己创建的测试问题。权限测试请求执行无副作用的whoami，但测试工具拒绝请求，不批准执行。它不会回答、打断或终止原有聊天。测试结束关闭自己的服务；本机实测临时会话没有写入持久会话目录。

原有Codex配置不改动。可选MCP和Hooks通过测试进程的参数停用；如果本机限制让服务无法访问运行数据库，报告连接失败，不能将失败解释成Codex没有该能力。系统通知、声音替换和现有桌面实时桥接未在本模块启用。

## 文件职责

| 文件 | 作用 |
| --- | --- |
| rpc.py | 带超时的stdio通信、请求编号匹配、只读模式和测试会话操作边界 |
| storage.py | 只读历史元数据；明确标记不具备权威实时等待状态 |
| state.py | 按准确会话关联任务；仅进行中/待操作自动流转，保留时间提醒标记 |
| __main__.py | 现有桌面检查和真实临时会话测试；输出状态记录 |

规则层拒绝串会话、旧轮次、旧关联、重复事件及未知等待标志；断线不判断成功。请求已解决不等于AI恢复，必须等真实运行信号。失败与中断分别记录，其移列细节仍待产品确认。该层目前作用于独立的测试任务对象，并未修改面板任务。

## 当前结果

2026-10-14，两个真实临时会话已验证正常结束、等待回答、回答后恢复、权限请求及拒绝后的继续处理。现有桌面聊天的准确编号和历史轮次可读；共享代理未接通，另起服务对原聊天返回notLoaded，尚不能旁路获得该聊天的全部实时状态。
