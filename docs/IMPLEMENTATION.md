## 0.9.4常用速度与重复开合（2026-10-15）

快速反向白条缺失的可触发路径：RevealScroll沿用旧进度，并将时间乘剩余距离；收起尚在准备时重新展开，from可能仍为1，从而跳过泛光并只运行1ms。现在画卷固定100ms，裁口延续当前位置，泛光按本次方向独立重新起算；初始打开和最终收起的白芯保持至首尾帧，防止100ms短动效合成端点漏掉25ms光效。不改变球与列的时间线。

OutsideClickObserver原在界面线程注册WH_MOUSE_LL。系统会静默移除超时低级钩子，界面重绘/布局耗时期间存在检测失效路径；依据[微软LowLevelMouseProc说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)。改为独立消息线程，仅记录物理位置、原始按下时间和工作区代次并立即返回；有序Channel工作队列负责原生命中，再投递界面处理。原生命中也与钩子分离，避免WindowFromPoint消息等待影响监听。保留真实点击才收起、内部单双击、菜单/原生对话框和代次过滤；没有重启或轮询强行收起。真实测试将隔离界面故意阻塞1700ms，阻塞期间及恢复后的外部点击均有效，恢复同一窗口和输入。

编号只改40×40圆形，底色白边不变；X仍48×40。暂存Switch开始合成时间由LiveBackdrop直接登记，准备期和动画前2/3不接受后续切换；最后1/3只接受一个pendingSwitch，不覆盖。WPF点击和动画中原生命中均使用原始按下时间，提前事件晚到也忽略；交接完成后才执行登记的切换，新动作清掉被中断的旧登记。

用户允许未重现的多白条项跳过。专项隔离三张暂存仅看到一个贯穿宿主的泛光层，不作未经验证的多图层修补。原采样记录保留，短闪可能漏采的失败不伪装成通过。采样器改为从一次原生画面读取六行统计光条，PNG写入移至采样结束，避免保存图片阻塞25ms闪光采样；重复整组恢复及快速重开另设实机验收，旧固定等待改为等待真正开合结束。

最终证据以VERIFICATION-0.9.4.json和ACCEPTANCE-0.9.4.md为准，完整便携包见BUILD-INFO-0.9.4-standard.json。未操作正式任务数据、用户进程或GitHub。

按用户确认实施U32至U37、A50至A55、T52至T58。列表配置使用稳定身份与内置角色，旧六列数据自动兼容。名称不驱动业务；灵感库、进行中、待操作可隐藏和改名，不可删除；正式任务、非空草稿或编辑原值仍引用的列表不能删除。删除空列保留身份，撤销任务删除或移动时恢复原列。隐藏不计入显示数量；整体布局和缩放只涉及可见列，零列情况下不计算无效外框。设置导入保留现有任务所需的列表定义，不修改任务数据。

CodexRpc和CodexObserver移植codex_probe的只读通信及规则。RPC允许方法白名单，IO在后台执行，准确会话编号、关联代次、来源批次、轮次与事件顺序分别校验；监听不替用户回答、批准、执行或恢复会话。编辑中选择现有聊天或粘贴编号，保存才改变正式关联。本机历史目录可读，当前原桌面实时桥接未连通；明确待确认，不把历史状态当成运行。只有可信事件让进行中/待操作互相流转，时间红点由用户操作清除，失败/中断单独显示。配置备份只含程序路径和本机端点，具体会话关联属任务数据。[官方只读会话接口](https://learn.chatgpt.com/docs/app-server)支持本轮通信边界。

圆球用Ellipse及CompositionEllipseGeometry直接绘制，保留40%透明度；不使用整数HRGN切圆。托盘和应用图标使用同一矢量图案生成的多尺寸ICO。原生圆外鼠标命中返回透明，最终桌面像素另外验证圆外无底板。预览范围使用物理坐标，覆盖球、小窗口及上下连接通道；区外才延迟收起。

列表向下及搜索条向左的100ms动画由Windows合成线程播放，将一次生成的UI表面与实时HostBackdropBrush一起裁剪。每帧不截取桌面、不用DispatcherTimer反复生成HRGN。WPF动画帧率元数据为120，拖动以8ms上限检查指针变化、位置未变不提交；这不等于声明计时器次数就是实际帧数。启动在屏幕外预热真实输入表面，复用UI像素纹理，批量更新窗口层级。隐藏时同步取消动画及隐藏内部绘制表面，防止残留；完成动画先恢复实际输入表面，再交接合成图层。截图只缓存短动画中的UI，动态背景仍由系统采样。[异步合成提交](https://learn.microsoft.com/en-us/uwp/api/windows.ui.composition.compositor.requestcommitasync)用于及时提交，帧率与桌面计数按[微软DWM时序定义](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ns-dwmapi-dwm_timing_info)分别记录。
