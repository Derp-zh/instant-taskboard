# 即时任务看板 0.9.30 使用说明

本地版本，未上传GitHub。先自行从托盘退出旧看板，再打开新目录里的“即时任务看板.exe”。任务和配置仍沿用原来的位置，不需要退出或重启Codex。

## 设置怎么用

设置左侧分为日常偏好和平台连接，共七页：常规、窗口与列表、通知声音、归档、数据与备份、AI平台、飞书。

- 常规：灵感快捷录入、悬浮球吸附、快捷键、开机启动与快捷方式。启动诊断收在展开项里。
- 窗口与列表：管理显示的列表和名称、透明度、尺寸入口及恢复默认。
- 通知声音：设置监听与提示音；捕获方式、权限及应用匹配等细节按需展开。
- 归档：调整归档规则，查看及恢复已归档任务。
- 数据与备份：先显示配置备份与恢复；任务和配置的保存位置放在“存储位置”中。
- AI平台：查看Codex连接和已关联聊天的实际能力；其他平台如尚未接入，会直接说明。
- 飞书：显示当前接入情况，不再放置尚不能使用的连接表单。

设置继续自动保存，右上角也可以立即“保存设置”。涉及快捷键应用等独立操作，仍使用原来的按钮。

## 连接Codex

1. 正常打开Codex。
2. 进入设置→AI平台，点击“检查连接”。只检查本地聊天列表和本机连接，不发送消息、回答问题或批准操作。
3. 在任务阶段选择已有聊天，或继续使用原来的拖动绑定。
4. “测试已关联聊天”查看看板已经收到的状态，不额外关注聊天。连接成功、聊天列表可读和具体聊天可观察会分别显示。

系统会自动寻找Codex。只有位置失效时才需要展开诊断，手动选择桌面程序。普通连接不需要CLI、旧服务地址或观察端口；旧配置值保留。

## 本版接入的取舍

聊天目录继续直接只读电脑已有的数据库，不为列聊天启动Codex辅助服务。文件中的“进行中”不再直接让卡片进入进行中，也不会凭文件清掉等待提醒。只有可靠实时状态才确认执行、提问、批准及真正恢复。

发现可能活动的聊天后，可以进行一次有限时间的状态观察。旧记录、文件写时间变化、读取失败和重连不会反复重开同一发现窗口；确认空闲后退出观察。已经确认的长时间运行或等待仍持续观察，以接收后续恢复。

读不到可靠状态时保留已有待处理保护，显示“待确认”。如果一个极短轮次从未被实时捕获，仅凭首次出现的文件记录不能可靠判断它属于新结果还是旧历史，所以本版不会据此自动移动卡片。已实时确认过的同一轮次，可以从准确落盘终态补齐结束。

本版完成的是接入整理和设置重排，尚未实现严格无订阅、完全不影响闲置释放，也没有量化公网流量节省。实际验证范围见同目录的ACCEPTANCE-0.9.30.md。
