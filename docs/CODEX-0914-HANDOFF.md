## 已核实的三个问题

### 1. 本机没有接通原桌面会话的实时来源，是用户当前症状的主要原因

`src/Taskboard.Desktop/CodexObserver.cs` 的 Run 先尝试共享服务代理；失败且未配置 endpoint 时，退回自己启动的独立历史服务，并将 Authoritative 设为 false。`src/Taskboard.Core/CodexState.cs` 的 Apply 会拒绝非权威来源更新任务状态。这个保护应保留，否则历史记录会冒充当前运行状态。

本次只读检查发现：本机没有配置 endpoint，且至少有1个绑定会话的运行阶段位于可自动流转的范围，不能仅归因为用户没有绑定或任务放错列。未记录用户任务名、聊天内容或会话 ID。

使用用户运行的0.9.14原包，在新建隔离目录实际运行 `--codex-verify`：能读到32个会话，但报告为 `liveTransportConnected:false`、`metadataOnly:true`、状态“历史服务可读 · 实时状态待确认”。所以目录可选、关联可存，不能证明原桌面聊天的提问/审批/结束能传到看板。

### 2. 观察器只有状态轮询时，存在正常结束识别缺口

同一观察器循环只调用 `thread/read`，且 `includeTurns=false`，不调用 `thread/turns/list`。若没有收到 `turn/completed` 通知，只看到 active → idle，则 Core 保留之前的 Running。idle 本身不能证明成功结束，这个判断正确；缺的是准确轮次的终态补查或可靠事件订阅。

已新增独立工具 `tools/CodexReleaseAudit`，加载0.9.14原包的观察器、RPC和 Core，用受控服务回复驱动原观察器真实事件回调。结果：active → waitingOnUserInput 可以移待操作，恢复 active 可以回进行中；随后 idle 时仍停在进行中，轮次补查次数为0。

这证明原包在该可复现条件下有缺口，**不是原 Codex 桌面全流程验收**，也不表示本机已有可用实时桥接。工具没有调用 BoardController 的桌面渲染和正式保存链。

### 3. 诊断通过的范围与用户期望不一致

`src/Taskboard.Desktop/CodexChecks.cs` 只检查目录和只读限制，目录非空便写 `passed:true`，即使同时报告 `metadataOnly:true`。它不能证明自动移列通过。请将目录检查、实时来源、逐会话能力、原桌面生命周期、面板移列验收分别报告；缺少原桌面验证时，完整接入验收不得显示为通过。

之前独立模块确实跑过真实 CLI 临时会话，但那些是模块自己管理的 ephemeral 会话，不是用户桌面里新建并关联的可见会话。它们不能覆盖本次问题，不能作为正式接入完成证据。

## 建议的修复顺序与边界

1. 先确认本机 Codex 桌面版本实际支持的共享事件来源或逐会话实时读取能力。必须用原桌面会话验证来源身份、问题/权限状态、恢复和结束；仅连上某个 app-server 或读取同一历史库不算成功。官方协议资料可参考 https://learn.chatgpt.com/docs/app-server ，具体以本机版本与实测为准。
2. 若可取得原会话可靠实时来源，接入现有观察器，按实际能力报告是否可用；保留历史只读降级，降级时不凭猜测自动移列。不要直接把 Authoritative 改为 true。当前“连接成功即权威”的推断也需要按真实来源与逐会话能力验证。
3. 增加轮次终态对账：优先准确事件；需要补查时先核实本机 `thread/turns/list` 等只读接口的参数、分页、顺序和终态字段。记录绑定基线、已观察当前轮次及已处理终态，不能因为旧历史最后一轮已完成而错误移列。断线重连、运行后才绑定、解绑重绑、轮次交错都要防止旧终态重放。未知/空闲不能直接等同完成。
4. 同步修正诊断和验收输出，明确 metadata-only 与 live 能力、原桌面验证状态和真实移列结果。为重现的问题添加有区分力的回归：完成事件缺失但存在可靠当前轮次终态时应补查；只有旧完成记录或只有 idle 时不应误移。
5. 若原桌面当前版本确实无法旁路获取所需实时信号，明确记录证据和无法支持的场景。若只能改成由看板启动/托管 Codex、安装插件、重新启动桌面或用其他方式改变用户工作流，先给用户具体选择和效果，不能悄悄切换成面板自有 CLI 会话。Windows 通知可做音频提醒，不能自行冒充准确会话关联和恢复信号。

观察器继续只读；不要为了订阅而接管用户聊天、自动答题/批准、重新执行原轮次。不要将所有未知状态移入待操作。不要恢复0.9.15已删除的卡片状态行或改动既有窗口动画、点击范围等无关行为。

## 修复后必须完成的验收

用独立 `--data-dir` 的看板和明确标记的测试聊天，保留用户正式任务和原有聊天。需要鼠标键盘操作前先协调用户；不得擅自操作用户正在编辑的内容。

1. 在用户实际 Codex 桌面新建可见的测试聊天 A/B，绑定隔离看板的运行阶段。不能以审计夹具或自己托管的 ephemeral CLI 会话替代。记录所用版本、信号来源和对应轮次，不把聊天正文写入交付。
2. 在真实桌面中分别触发：正常结束、结构化提问、权限请求；看板实际进入待操作。用户回答/批准后等实际执行恢复，再实际回进行中；若回答后直接结束则按真实终态处理，不强造运行状态。未能触发的场景写未验收。
3. A/B 交错执行不串任务；多运行阶段等待优先；未运行阶段及其他四类/自定义列不自动移动。
4. 执行后才关联、离线/重连、解绑重绑、旧完成记录不误移；缺少完成事件时的补查与幂等可由回归夹具补充，但原桌面主流程仍需实测。
5. 时间提醒到期显示红点，用户主动操作后清除；Codex 确实恢复执行、任务回到“进行中”时，也同时清除红点。仅收到回答或批准、尚未恢复执行时，不以“已恢复”为由清除红点。编辑过程中后台状态及红点更新不被保存草稿覆盖。
6. 验证实际卡片所在列及保存后的结果，而不只调用状态函数。交付写清原桌面通过项、夹具通过项、隔离路径和未验收项；完成前不要声称“Codex 接入正常”。
