## 新发现及隔离原型

1. 已验证的管道路由器在发送时按targetClientIds筛选实际socket；普通连接不能旁听发给其他follower的snapshot／patch。initialize分配新的clientId，不能靠填入现有客户端编号取得它的状态。
2. 已核实的owner注册器仅登记18条明确路由；四个内部getter未在该注册器中暴露。即使放宽版本校验，所提取的发现／请求方法仍因缺handler拒绝这四个getter。owner discovery只返回能力标记；following-status query只返回订阅协调消息，不返回聊天快照。此结论限定于所查注册器与通道，未穷尽其他动态注册和整个安装包。
3. 直接回放安装包broadcastIpcStatePatches：无follower时，状态变化不会递增streamRevision。合成Map替换调度复现“版本前后相同，但读到已解决的旧请求”。因此双读发布版本不能证明外部堆快照一致，更不能安全清等待或判定恢复。
4. native只读PE元数据取得chrome.dll的精确V8版本15.5.35.23和导出函数；有10个Node debug offset，但所查导出表没有完整V8布局表，app根无PDB。GetCurrent／HeapSnapshot等函数需目标运行时上下文，不能从外部把导出函数当成现成状态接口。没有调用这些函数。

独立原型为静态提取工具（本地归档）、原方法回放（本地归档）及PE元数据工具（本地归档）。13项回放通过，仅属于合成socket／对象／调度，不是原桌面完整读取原型。完整对象契约和后续前置条件见内存路线审查（本地归档）。
