# 现行规则与索引维护

2026-10-21起采用。权威行为在[current](current/README.md)，产品交付状态在[STATUS](current/STATUS.md)，代码事实在源码，Codebase Memory用于定位。旧版本原文/验收是追溯证据，不作为日常平行生效规则。

## 每次需求变更

1. 读HANDOFF、INDEX后，只选目标模块及受影响共享规则。代码优先index_status→get_architecture→search_graph/trace_path/get_code_snippet，缺口/断连用rg定点核对并如实说明。
2. 将用户明确的新要求直接改入对应现行条目，同时改该页验收。保留稳定模块规则编号；被替换的旧行为移出有效正文，不追加“本版本覆盖前文”。当前未改的有效条目保持，建议/待确认单独标明。
3. 实施前写明本次改变、保持项、消费者与所选回归；重要且无法从已确认要求解决的冲突再给用户选项。源码与需求矛盾时，不默认把现有错误实现升级成需求。
4. 更新TASKS的实际状态、STATUS的交付/验收边界及必要的共享代码表。未实测不勾通过，未知/未支持/未验收分别写。版本证据文件保持原时点，不为整理改写历史失败。
5. 先验证文档，再刷新代码索引及其摘要。摘要只存版本、权威文件路径、能力边界、源码定位，不再复刻全套规则或追加多份“当前交付”。索引成功不代替摘要更新，摘要成功不代替源码新鲜度检查。

## 默认读取与检索

- HANDOFF只保留当前入口、注意事项和风险；INDEX只做路由；PRD只做现行规则总入口；TASKS只保留当前任务/模块依赖/缺口。历史时间线不默认加载。
- 文档检索优先限制`docs/current/`及本轮涉及的源码路径。历史从`docs/history/`、版本化ACCEPTANCE/VERIFICATION或legacy按需取证，不全局搜出旧规则后自行猜覆盖关系。
- 只有用户明确追溯、修复依据不足或核查遗漏时才读历史。以前的PRD第40/43节、R/U/A编号可用[迁移对照](history/20261021-before-current/coverage.json)找对应现行模块，不必按时间从头读。
- `.cbmignore`排除新整理的历史快照，Codebase Memory摘要须指向current。工具不可用时，用本地权威入口继续工作，记录实际错误和待同步内容；不能声称已刷新。

## 结构检查

在仓库根目录运行`python tools/check_current_docs.py`。检查当前链接/锚点、旧需求编号是否都有模块归属、快照SHA256、现行页是否出现已废弃的关键规则、索引摘要待同步文件与权威入口的一致性。它不能证明所有自然语言语义正确，也不代表产品测试通过。

一次性整理来源及替换关系在[迁移说明](history/20261021-before-current/README.md)。后续只改本轮相关页，不反复重新导入全部历史。
